Change Log
==========

### 3.1.0 - 2026-11-07

#### Breaking changes
* Updated the Urban Object module (`uro`) to version 3.1 of the i-UR ADE (schema 3.1.2). The database schema for
  `uro` was regenerated with the ADE Manager Plugin and is not compatible with the 2.0 schema; `urf`, `urg` and
  `urt` are unchanged. The disaster risk, key-value pair and data quality attributes are now shared types with
  their own tables (`ur_disasterriskattribute`, `ur_keyvaluepairattribute`, `ur_dataqualityattribute`,
  `ur_publicsurveydataqualit`).
* Import/export of the i-UR 3.1 building attributes `buildingIDAttribute`, `buildingDetailAttribute`,
  `largeCustomerFacilityAttribute`, `bldgDisasterRiskAttribute`, `bldgKeyValuePairAttribute`,
  `bldgDataQualityAttribute` (with `publicSurveyDataQualityAttribute`), `bldgRealEstateIDAttribute` and
  `bldgUsecaseAttribute`.
* Updated iur-ade-citygml4j to 3.1.0.

#### Changes
* The column `offset` generated by the ADE Manager for `OffsetDepth` is renamed to `offset_` in the DDL and the
  schema mapping because `offset` is a reserved word in PostgreSQL.
* Repeated ADE properties (disaster risks, key-value pairs) are exported in import order (`ORDER BY id`).

#### Changes (all uro attributes, 2026-11-07)
* Import/export of every `uro` generic application property of every CityGML feature type defined by the i-UR 3.1 XSD,
  including GML geometries of DM attributes and the ifc coordinate reference system properties.
* The ADE Manager output is patched where it cannot represent the schema (multi-valued dates, the
  `IfcCoordinateReferenceSystemSelect` choice, inline `IfcAxis2Placement3D`, property injections with a wrong base type).
* Importers, exporters and schema registrations are generated from the schema mapping by the `iur-ade-generator` repository.

#### Changes (ADE feature types, 2026-11-07)
* Import/export of the ADE feature types of the i-UR 3.1 Urban Object module (`uro:OtherConstruction` with its boundary
  surfaces and installations, `uro:UndergroundBuilding`, `uro:Waterway`, `uro:PublicLand` and the utility network
  elements), one importer and exporter per table in the style of the `urf` feature classes. Nested features are imported
  through the Importer/Exporter with the parent id as foreign key and exported through the extension's own exporters
  (the Importer/Exporter creates nested ADE objects as stubs).
* `OtherConstruction` and `UndergroundBuilding` are marked top-level in the schema mapping (the ADE Manager left them
  without `topLevel`).

#### Changes (Urban Function module, 2026-11-07)
* **Breaking:** import/export of the Urban Function module (`urf`) version 3.1 of the i-UR ADE: 131 feature types and
  29 data types. The `urf` tables are generated in the style of the ADE Manager (`iur-ade gen-mapping` of the
  `iur-ade-generator` repository; the ADE Manager itself does not finish the transformation of the urban function
  hierarchy) and replace the 1.4 tables; every concrete `urf` feature is top-level, references between members and
  `urf:target` are join tables exported as xlinks.
* **Breaking:** multi-valued data type properties of all modules are stored in join tables (`ur_<owner>_to_<type>`)
  instead of one foreign key column per owner in the type's table: the Importer/Exporter orders its batch commits by
  table weights summed along the schema mapping joins in `int` arithmetic, and the shared `uro` data types made the
  weights overflow, which scrambles the commit order (foreign key violations on import). An owner with several list
  properties of one type keeps the foreign key columns (the ADE Manager's delete functions reject two join tables
  between the same tables). Subtype rows are deleted with their base rows (`ON DELETE CASCADE`).
* Lists of simple values and of measures are stored as joined strings like the lists of dates.

#### Known limitations
* `gml:pos` values (`uro:Elevation/elevationValue`, `uro:OffsetDepth/pos`) keep their coordinates only; `srsName` and
  `srsDimension` are not stored.
* `urg` and `urt` remain at 1.4.
* `impexp delete` leaves the rows of data types reached through join tables and the nested `uro` features behind
  (the delete functions generated by the ADE Manager treat join tables as aggregations).

### 3.0.0 - 2026-11-07

#### Breaking changes
* Updated the Urban Object module (`uro`) to version 2.0 of the i-UR ADE. The database schema for `uro` was
  regenerated with the ADE Manager Plugin and is not compatible with the 1.4 schema. The `urf`, `urg` and `urt`
  parts of the schema (table names, schema ids) are unchanged.
* Import/export of the i-UR 2.0 building attributes (`BuildingIDAttribute`, `BuildingDetailAttribute`,
  `LargeCustomerFacilityAttribute`, `BuildingDisasterRiskAttribute` subtypes, `KeyValuePairAttribute`,
  `BuildingDataQualityAttribute`).
* Removed the 1.4 `uro` handling of LandUse and TransportationComplex properties. The 2.0 attributes of LandUse,
  Road, TrafficArea, CityFurniture, Vegetation and WaterBody are stored in the schema but not yet imported/exported.
* Updated iur-ade-citygml4j to 2.0.0. The module is currently consumed from `mavenLocal()`
  (`gradlew publishToMavenLocal` in the iur-ade-citygml4j fork).

#### Fixes
* The `urf` and `urg` CityObjectGroup property exporters used the `uro` namespace for projection filtering.

### 2.1.0 - 2024-09-19

#### Changes
* **Breaking:** Java 11 is now the minimum required version for using the i-UR ADE extension.
* Updated impexp-client-gui to 5.5.0.
* Updated energy-ade-citygml4j to 1.5.0.

### 2.0.0 - 2021-10-08

#### Changes
* Updated PostgreSQL database schema to use 64-bit `bigint` as data type instead of 32-bit `integer` for all
  primary key and foreign key columns. Hence, this release can only be used with version 4.2.x of the 3DCityDB.
  It is not compatible with previous versions of the 3DCityDB anymore.
* Updated impexp-client-gui to 5.0.0
* Updated iur-ade-citygml4j to 1.4.2.
